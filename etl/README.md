# ETL — 정책 데이터 구축 파이프라인

이 디렉터리는 정책 공고문을 표준 스키마로 정형화하기 위한 **오프라인 데이터 구축 도구**입니다.

## 서비스 실행 경로와의 관계

```
[ETL: 오프라인, 수동 실행]           [서비스: 런타임]
공고문 → 정형화 → staging → 검토  →  DB  →  policy_filter → graph_builder → MWIS 솔버 → 결과
                                     ↑
                              여기서부터가 서비스
```

- 웹 서비스(`backend/`)는 이 파이프라인을 **호출하지 않습니다.**
- 사용자 요청을 처리하는 최적 조합 계산은 전적으로 **결정론적 MWIS 알고리즘**으로 수행되며, 추론 모델이 개입하지 않습니다.
- ETL은 개발자가 데이터를 갱신할 때 수동으로 실행하며, 결과는 staging 단계의 **사람 검토를 거쳐** 반영됩니다.

## LLM 사용 범위

정형화 단계에서 상용 LLM API를 사용합니다. 사용 범위는 **비정형 공고문 텍스트를 구조화 JSON으로 변환**하는 것에 한정되며, 다음은 자동화하지 않습니다.

- 정책 간 배타 관계(`exclusive_with`)의 UUID 매핑과 양방향 보정
- `is_supplementary`(MWIS 후보 여부) 최종 판정
- 수혜액 산정 결과의 채택

위 항목은 배타 그래프의 정합성에 직결되어 오류 하나가 최적해 전체를 오염시키므로, 공고 원문 대조를 거쳐 사람이 확정합니다.

## 실행

```bash
cd etl
pip install -r requirements.txt
python run.py          # 수집 → 정형화 → staging 적재
python promote.py      # 검토 완료분을 운영 테이블로 승격
```

환경 변수는 프로젝트 루트 `.env`를 따릅니다.
